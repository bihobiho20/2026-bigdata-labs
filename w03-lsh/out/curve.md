## 데이터와 측정 범위

bench.build()의 2,120개 제한을 task2_crossover.py에서 보완했다. 이하는 기존 데이터의 앞부분을 사용하고, 이후에는 고정 시드 247로 어휘 5,000개에서 shingle 60개씩 뽑아 추가했다. 기존 유사 문서 120개 추가는 유지했다. bench.py는 수정하지 않았다.

실제 문서 수가 n이고 완전탐색 비교 횟수가 n(n-1)/2인지 모두 확인했다. 9개 크기, 125~8,000의 64배 범위로 A1을 충족했다.

시간은 find()의 wall time으로 tracemalloc 비용을 포함하며, 문서 생성과 finder 생성자는 제외한다. 메모리는 find() 중 Python 할당의 peak로, 입력 데이터 생성과 프로세스 전체 RSS를 제외한다. Task3의 bench.txt는 tracemalloc 없이 측정하므로 시간을 직접 비교하지 않는다.

## 두 배 크기의 시간 증가율 (A4)

| n 변화 | 완전탐색 시간 비율 | LSH 시간 비율 |
|---|---:|---:|
| 125 → 250 | 4.037배 | 1.336배 |
| 250 → 500 | 4.083배 | 1.443배 |
| 500 → 1,000 | 4.082배 | 1.604배 |
| 1,000 → 2,000 | 4.139배 | 1.727배 |
| 2,000 → 4,000 | 3.941배 | 1.799배 |
| 4,000 → 8,000 | 3.914배 | 1.928배 |

완전탐색은 3.914~4.139배로 대체로 4배에 가깝고, 비교 횟수도 n(n-1)/2와 일치해 이차 증가가 관찰됐다. 작은 측정 구간과 실행 부하 등이 오차에 영향을 줄 수 있지만, 원인을 분리하는 반복 실험은 하지 않았다.

## 속도 교차와 초기 비용 (A7·A8)

875개에서는 완전탐색 1.5866s < LSH 1.7234s였고, 1,000개에서는 완전탐색 2.1599s > LSH 2.0439s였다. 교차 구간은 875~1,000개이며, 측정한 크기 중 LSH가 처음 빨라진 값은 1,000개다. 단회 측정이고 차이가 작아 정확한 교차점은 확정할 수 없다.

LSH는 비교 전에 shingle 정렬과 행 번호 변환, 서명 배열 할당, 120개 해시 계산과 최솟값 갱신, 30개 band의 tuple·버킷·후보 집합 생성을 수행한다. Task1 구현은 각 행마다 모든 열의 포함 여부도 확인한다. 작은 n에서는 절약하는 비교보다 준비 비용이 크다. 어휘 수가 고정된 이번 실험에서 준비 비용은 n에 대체로 선형이지만, 어휘 수도 늘어나면 비용이 더 커질 수 있다.

## 최대 크기와 중단 기준 (A2·A5)

8,000개에서 완전탐색은 137.87s, LSH는 12.24s였다. 완전탐색 한 번이 1분을 넘겨 시간 부담 조건에 도달했으므로 확대를 멈췄다. 메모리 부족이나 실행 실패는 발생하지 않았다.

최대 크기의 peak는 완전탐색 19,144 bytes (18.70 KiB), LSH 30,129,856 bytes (28.734 MiB)였다. 완전탐색은 전체 쌍을 저장하지 않고 순차 비교해 추가 할당이 작으며, LSH는 변환한 열·서명·버킷을 저장한다. 입력 데이터까지 포함한 총 메모리 비교는 아니다.
